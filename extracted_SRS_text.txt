WINTER ARC \001 SOFTWARE REQUIREMENTS SPECIFICATION Version 1.0 WA-SRS-001 Page 4 1. Introduction 1.1 Purpose This Software Requirements Specification defines the complete requirements for Winter Arc, a responsive web application designed to help users organize a defined period of personal improvement through goals, habits, tasks, study/workout tracking, journaling, analytics, reminders, and gamification. The specification is intentionally implementation-aware so it can guide both academic development and a portfolio-quality production build. 1.2 Problem Statement People commonly set improvement goals but lack a single system that connects long-term goals with daily execution and measurable outcomes. Winter Arc addresses this gap by combining planning, daily execution, reflection, progress measurement, and feedback in one application. 1.3 Objectives \001 Provide a structured framework for a user-defined transformation period. \001 Convert high-level goals into measurable tasks and recurring habits. \001 Provide a daily dashboard showing what matters today. \001 Capture study, fitness, productivity, mood/energy, and reflection data without making any one category mandatory. \001 Provide historical analytics so users can identify patterns in their own behavior. \001 Use gamification to reinforce consistent execution without making rewards the primary purpose. \001 Provide a secure backend and normalized relational database. \001 Expose REST APIs so the frontend can later be replaced or expanded with React. \001 Create an architecture that can accommodate future AI/ML recommendations. 1.4 Intended Audience \001 Student/developer implementing the project. \001 Project evaluator or academic supervisor. \001 Future contributors maintaining the codebase. \001 End users using the application for personal planning and tracking. 1.5 Document Conventions Requirements use identifiers such as WA-AUTH-001. Priority terms MUST, SHOULD, and MAY indicate implementation priority. A MUST requirement is part of the acceptance baseline unless explicitly deferred to a later phase.

Security and Privacy Requirements 12.1 Authentication Security \001 Use Django's proven password hashing framework. \001 Use HTTPS in production. \001 Secure cookies must use appropriate Secure, HttpOnly and SameSite settings. \001 CSRF protection must remain enabled for cookie-authenticated browser workflows. \001 Authentication endpoints should be rate-limited. \001 Secrets must be supplied through environment/secret management rather than committed to source control. 12.2 Authorization \001 Object-level authorization is mandatory for all user-owned records. \001 An administrator must not automatically receive unrestricted access to private journal content unless a documented operational requirement exists. \001 API permissions and web permissions must enforce the same ownership rules. 12.3 Input and Application Security \001 Validate all server-side input even when client-side validation exists. \001 Use ORM parameterization; WINTER ARC \001 SOFTWARE REQUIREMENTS SPECIFICATION Version 1.0 WA-SRS-001 Page 31 24. Glossary Term Definition Arc A defined personal-improvement period with start/end dates and an objective. Goal A measurable or status-based outcome the user wants to achieve. Milestone An intermediate checkpoint within a goal. Task A discrete action that can be scheduled and completed. Habit A recurring behavior tracked over time. Streak A consecutive sequence of expected habit periods completed. Check-in A daily record containing optional self-reported metrics and reflection. XP Experience points awarded for defined eligible actions. Achievement A badge/unlock triggered by deterministic criteria. REST API HTTP-based interface exposing application resources and operations. ORM Object-Relational Mapping; Django ORM maps Python models to database tables. JWT JSON Web Token, commonly used for stateless API authentication. CSRF Cross-Site Request Forgery; an attack mitigated by request authenticity controls. XSS Cross-Site Scripting; injection of executable content into web pages. Celery Python task queue used for asynchronous/background jobs. Redis In-memory data store commonly used as cache or message broker. Idempotency Property where repeating an operation does not incorrectly duplicate its effect. NFR Non-Functional Requirement, such as performance, security or usability. MVP Minimum Viable Product; smallest release satisfying core user value. AI/ML Artificial Intelligence / Machine Learning functionality added after reliable core data collection.
